# Eggnog.Relations design decisions

These decisions bind every change to the engine. They settled the open questions of the engine's design (recorded in
[`../history/egglog-engine-map.md`](../history/egglog-engine-map.md), "Open questions"), whose cross-cutting decisions
for colored contexts ("Cross-cutting decisions" there) hold as written unless a line below refines them.

| # | Question | Decision |
|---|---|---|
| 1 | Deletion across contexts | A context with live descendants must not retract rows (delete, `clear_table`); the attempt throws. A child retracts a shared table's rows only under a frozen parent. Tables declared *context-private* (for example scheduler bookkeeping) are exempt, because descendants never read them. A child may delete its own rows (tombstone) and hide visible ancestor rows. A subsume is not a retraction. It is a sticky value change of the row's subsumption cell, merged like an output, and allowed wherever a write is. That includes a child under a writable parent, and a root or child with live descendants: the descendants see the subsumed row when they catch up, and the subsumption survives a later union that rewrites the row. `RetractionGuard` has no subsume check (`ChildSubsumeAndDeleteTests`). The library's `Scope.Delete` and `RuleBuilder.Delete` are egglog's `delete` under these rules, refused before any work where the guard would refuse them (`docs/architecture.md`, section 2.5); a rule callback's `Remove`, which only the callback decides on, is refused when made, failing the rule. |
| 2 | Non-lattice merges | Merge functions declare whether they are lattice merges (associative, commutative, idempotent). A non-lattice merge (`new`, `old`, arbitrary primitives) is allowed only in a context that has no ancestors (the root). Writing such a table from a child throws. The library's `FunctionMerge` functions are such tables, and the library refuses what would write one below the root before any work wherever it can tell (`docs/architecture.md`, section 2.3). |
| 3 | Which classes to mark | Only losers: when a child's union makes a class lose, the child hides and copies the ancestor rows that mention the loser, and rows that mention the winner stay visible. Probes for a canonical value filter hidden rows instead of skipping the parent. |
| 4 | Determinism | Serial execution is deterministic for a given program. Parallel execution must produce the same view modulo renaming of ids and the same set of facts; numbering may differ. Golden tests run serially. The exception is a merge that is not associative, such as `KeepIncoming`, which only the root may have (decision 2; the library's are `FunctionMerge`'s). The parallel insert folds each batch before merging it into the stored row, and batches from different threads arrive in no fixed order. So a table with such a merge may differ from a serial run in its values, timestamps and change reports, as in egglog (`MergeFunction`, `src/Eggnog/Relations/Tables/MergeFunction.cs`). The root differential keeps such tables single-sharded under loads that go parallel (`DiffGenerator.RandomTable`). |
| 5 | Fresh-id scope | Match egglog: the predicted-value cache lives per `ExecutionState` (per batch), and merges union duplicates. |
| 6 | Match-count parity | Not required. Counts are reported but may differ from egglog's. |
| 7 | Plan parity | Fix egglog's planner defects (rows 5-7 of the defect list, "egglog defects: what the port does instead" in `egglog-engine-map.md`) instead of reproducing them; golden plan tests encode the fixed behaviour. |
| 8 | Executor | The interpreter is the only executor: no plan, stage kernel, right-hand-side program or merge function is compiled at run time (no expression trees, emitted IL or generic structs composed by reflection), so the engine needs no dynamic code. The interpreter keeps the recursion and dynamic reordering. Specialization is closed-world C#: fast paths for a bounded set of shapes, chosen by the interpreter's switches and tested against the general path; whether to build them is decided by a ceiling prototype (`docs/roadmap.md`, "Kernel specialization"). |
| 9 | Containers in children | Eq-sort containers in child contexts are not supported: interning an eq container from a child throws. Containers of values, the library's pairs and vectors, hold no ids and are interned in any context without an execution state, from the store's shared id counter. Adding them is part of the containers item of `docs/roadmap.md`, "Fidelity with egglog". |
| 10 | Rule-based rebuild | Dropped. Rebuild is the native incremental/full path only. |
| 11 | `IterationReport.changed` | Report whether the rule application changed anything; rebuild changes are reported separately. The scheduler decides saturation from both. |
| 12 | Primitives and capability contexts | As egglog: the engine has no capability contexts. External functions receive the raw `ExecutionState`, a trust boundary (`EGraph.RegisterExternalFunction`). The capability contexts (pure, read, write, full) belong to the layer above, which registers a primitive once per context it is valid in and picks the id per call site: a semi-naive rule uses pure on the left-hand side and write on the right, a naive rule read and full, merge functions write, one-shot commands full, `check` read. The bridge guarantees the discipline those contexts rely on: a left-hand-side primitive (`EGraphRuleBuilder.QueryPrim`) runs after the join on every match of every semi-naive variant and a result of nothing drops the match; a right-hand-side call (`CallExternalFunc`) that produces nothing panics; writes are staged and visible only after the run. With colored contexts, the `ExecutionState` a primitive receives is bound to its context, which is what makes `TableAction`/`UnionAction` context-correct. |
| 13 | Packaging | The engine is part of the `Eggnog` assembly and package, under `src/Eggnog/Relations` in the namespace `Eggnog.Relations`; there is no separate engine package. Its types stay internal, so the package shows one API, and the namespace is what tells engine types from the library's. Its tests are part of `Eggnog.Tests` (under `Relations/`) and its benchmarks of `Eggnog.Benchmarks` (under `Relations/`); both keep the engine's namespaces (`Eggnog.Relations.Tests`, `Eggnog.Relations.Benchmarks`) and reach it through `InternalsVisibleTo`. The library's own benchmarks are under `Library/` (`Eggnog.Benchmarks.Library`); `Eggnog.Tests` compiles the app's comparison sources as linked files to test them. |
| 14 | `u32` ids and clock | Ids and the clock stay 32-bit and are never reclaimed. 64-bit cells: dropped, because upstream egglog also uses 32-bit values and timestamps, and 64-bit cells would double the memory of every cell, in every table, index and probe, against a limit that retiring a graph on the gauge already handles. Global recycling of ids or the clock in place: dropped, because recycled ids break smaller-id-wins under a writable parent, and the global clock cannot be reset while a frozen scope's rows carry stamps. Ids and epochs local to the transient children of a frozen scope: possible, and deferred, because a host can retire a graph on the gauge (`EGraph.Usage`), once per graph life; the trigger is a host forced to retire graphs more often than it can afford. Every id-minting path applies one bound, `UnionFind.MaxId`, and the clock applies `Value.StaleRep`. Running out throws `OverflowException` and faults no context. |
| 15 | Compaction under live descendants | A table whose gate has live descendants does not compact, because compaction renumbers the rows their cursors and hidden sets name. A disposed child counts until its own children are disposed. A context frozen with live descendants keeps those tombstones for good, and the count of such tables is reported once the freeze completes (`Context`/`Scope.CompactionsBlockedAtFreeze`). Freeze neither refuses nor warns. Compaction above the highest live cursor is parked (`docs/roadmap.md`, "Parked"). |
| 16 | Trimming and NativeAOT | The library is trimming and NativeAOT compatible. `src/Eggnog` declares `IsAotCompatible`, and `src/Eggnog/Analyzers.globalconfig` makes its trimming, single-file and AOT analyzer warnings errors. CI publishes `src/Eggnog.AotCheck` with NativeAOT, rooting the `Eggnog` assembly, and fails on any IL2xxx or IL3xxx warning. Reflection must be annotated or carry a justified `UnconditionalSuppressMessage`; there are two: `ValueStore.RegisterMethod` (IL2067, message only) and `SExpression.DefaultLiteral` (IL2075; a trimmed sort renders by `ToString()`). This follows from decision 8: the interpreter is the only executor, with no dynamic code. |
| 17 | Proofs | Not followed yet. Upstream egglog builds proofs (`EGraph::new_with_proofs`, with the term encoding in its `src/proofs`); eggnog does not. Parked until upstream's proof API settles and ships in a release (`docs/roadmap.md`, "Parked"). A provenance of eggnog's own design (a record of the rule that first wrote a row) is dropped. |
| 18 | Scope and query lifetime | Scopes and queries are managed by the garbage collector, and `Dispose` is optional: it refuses new calls at once and releases as early as the tree allows. A scope lives while anything referencing it is reachable, and that keeps its ancestors alive too: a child, a local `Rule`, a `RunReport` with steps, an `Extractor`, `ExtractedTerm` or `NodeView`, a `CaseSet` or one of its cases, a `ScopeWriter`. A `ClassId` alone does not keep its scope. `Children` lists only the children that are still reachable. A dropped scope is released after a collection of the generation it reached, typically a full one for a scope that ran. Until then a dropped child keeps a writable ancestor from compacting and blocks a frozen tag's scoped reads; `Dispose` is the remedy, and compaction is not changed for it. A delegate the graph holds keeps what it captures, so a scope or query captured by a global rule, a split rule or a lattice is never collected, even after `Dispose`. Each non-root scope and each query has one private finalizable sentinel that only queues the release, and the graph one shared weak reference; this is the one exception to the rule of no finalizers (`../history/egglog-engine-map.md`, the `MutationBuffer` flush row). The release suppresses a scope's sentinel, `Dispose` suppresses a query's, and releases run on a thread-pool work item. A sentinel per scope is chosen over one finalizable object per graph, or none, because a scope that dies young is released after the collection that finds it, and a drain walks only the dropped scopes. It is built in phases (`docs/roadmap.md`, "Library work"); until then a scope lives until it is disposed (`docs/architecture.md`, section 2.12). |
| 19 | Departures that only remove allocation | A change that only removes allocation may depart from egglog, and lands only through its own timed gate (`docs/roadmap.md`). There are three. The first, which landed after its comparison, is header instantiation that evaluates into scratch the rule set builder owns, and allocates the instance's arrays only once every header is nonempty (the idle-rule allocation commit; roadmap, "Idle local rules"). The egglog files and lines this row cites are at `5e655cae`. For a single plan whose first header is empty, egglog allocates nothing either: its header vector is a lazy `vec![]`, which allocates on its first push, and its constraint lists are pooled (`core-relations/src/query.rs:191-215`, `core-relations/src/free_join/mod.rs:71-79`). So the change departs from egglog only where egglog allocates: for a decomposed plan, whose block vector egglog allocates before any header (`query.rs:216-241`), and when a header after the first is empty, once the first push has allocated the vector. The same commit rents a run's per-rule buffers in `EGraphContext.RunRulesCore` from the pool: each listing's rule info, cached plan and staged progress, and the repeat table of a long list. These depart from nothing, because egglog has no such buffers. Its `run_rules`, through `run_rules_impl` (`egglog-bridge/src/lib.rs:587-596` and `1397-1420`), takes the timestamp first, plans every rule, then adds each rule from its cached plan and sets the rule's `last_run_at` in place in its rule table. The port resolves and plans every listing before it advances the epoch, and stages each listing's progress, which it commits after the run. The rest of that commit sits on paths egglog does not have, or changes no result: the per-layer header buffers (egglog has no layers), the progress map a context sizes once (egglog keeps `last_run_at` in each rule's info), and rule statistics updated in place, which report what they did before. So does the cache commit (`idle-rule-cache`), which keeps each ruleset's iteration rule list and lowered variants on the nearest scope with local rules: egglog has no scopes or local rules. The other two, which egglog does not do and which are pending, are a bounded hash-index reserve at merge and staging arrays returned to the pool (`campaign/write-alloc`). |
| 20 | Subsumption in the library | The library exposes egglog's subsumption: the `subsume` action (`RuleBuilder.Subsume`, and a host's `Scope.Subsume` and `ScopeWriter.Subsume`) and `rewrite ... :subsume` (`RuleBuilder.Rewrite(left, right, subsume: true)`), over the engine's port of `can_subsume`, `combine_subsumed` and the subsume action (`egglog-bridge/src/lib.rs:1527-1531`, `rule.rs:472-522`). As in egglog: only relations and constructors can be subsumed (`SubsumeMergeError`, `src/lib.rs:2590-2598`); rule bodies match only rows that are not subsumed (`src/lib.rs:2525-2537`); lookups and the host's reads (`Check`, `Get`, `Rows`, `CountRows`) see subsumed rows, as `check_facts` (`include_subsumed`, `src/lib.rs:1475-1510`), lookups and `print-size` do; subsuming a missing row inserts it subsumed, a constructor's with a fresh id and its subterms made as usual; a subsuming rewrite subsumes its left side after the union (`src/ast/desugar.rs:306-357`); extraction skips subsumed rows. As in egglog, every relation and constructor has the subsumption column and no function has; a user may opt a table out (`TableOptions.Subsumable = false`), an addition that saves the cell on every row and the constant filter on every atom, after which subsuming it is refused, at definition for a rule and at the call for a host. The departures: (a) none for which tables are subsumable. (b) A query (`EGraph.DefineQuery`) and a split rule skip subsumed rows, as a rule body does, while egglog's one host query, `check`, includes them: a query is what a host loop matches with in place of a rule. (c) A rule that subsumes a missing row goes on to run its later actions for the match, and keeps a subsumption a predicted lookup would lose: the engine's fix of egglog defect 19 (`RuleAction.LowerSubsume`), which upstream made on its main branch after 3.0.0 too (`docs/egglog-3.0.0-todo.md`, "After 3.0.0"). (d) A subsuming rewrite subsumes the row its body matched, its left side's arguments taken from the match rather than evaluated again as actions, so a left side may read a function, which an Eggnog head may not. What egglog does not have: a subsumable relation read scoped gets a subsumable mirror and a second copy rule, which subsumes in the mirror the rows the tagged scope subsumed, so the mirror stays exact; and a lift writes the rows every case holds not subsumed (unless the parent subsumed them), because a case's subsumption is a choice to stop matching a row under that case's assumption, not a fact that holds in the parent. Across contexts a subsumption is a write (decision 1). |
| 21 | Variants in the library | The library exposes egglog's extraction of several variants, `(extract x n)`: `Extractor.ExtractVariants(class, count)` and `Scope.ExtractVariants(class, count, costs)`, over the engine's port of `extract_variants_with_sort` (`src/extract.rs:647-733`). As in egglog: a variant is one node of the class with its arguments' cheapest terms, costed as the node's head plus those terms; subsumed rows are not variants (`src/extract.rs:688`); the variants come cheapest first, equal costs by function name and then raw row values, so the first need not be the term `Extract` gives, at most `count` of them (`src/extract.rs:702-703`); a class whose nodes are all subsumed or unextractable has none. The departures: (a) a node with an argument that has no finite term is not a variant, where egglog unwraps its cost and panics (`src/extract.rs:691`); egglog 3.0.0 skips it too (`docs/egglog-3.0.0-todo.md`, "Extractor errors"). (b) A count of 0 gives no variants, as `extract_variants` does, where egglog's command `(extract x 0)` extracts the cheapest term (`src/lib.rs:1623-1636`): that is `Extract` here. A negative count throws `ArgumentOutOfRangeException` where the command panics (`src/lib.rs:1638`); egglog 3.0.0 returns an error (`docs/egglog-3.0.0-todo.md`, "Panics made errors"). What egglog does not have: in a scope, the variants are the nodes the scope sees (its own rows and its ancestors' not hidden there, none subsumed there) under its equalities; their classes carry the scope's origin, and staleness and threading are `Extract`'s. |
| 22 | Primitives in the library | The library's built-in primitives are egglog's, with egglog's names and results: the `i64`, `f64`, `bool`, `String` and `BigInt` primitives of `src/sort/` (`Primitives`, `DoublePrimitives`, `BooleanPrimitives`, `StringPrimitives`, `BigIntegerPrimitives`), the generic `bool-!=`, `ordering-min` and `ordering-max`, and the set primitives of a value set, the pair primitives (`pair`, `pair-first`, `pair-second`) of a pair of values, the vector primitives (`vec-empty`, `vec-of`, `vec-append`, `vec-push`, `vec-pop`, `vec-length`, `vec-contains`, `vec-not-contains`, `vec-get`, `vec-set`, `vec-remove`, `vec-range`) of a vector of values, with `BigInteger` a built-in value type and NaN a value of `f64` under `OrderedFloat`'s semantics (`OrderedDouble`). A primitive is partial where egglog's is a `-?>` primitive (`Primitive.IsPartial`): a call with no result drops the match in a body let, a filter and a query, as in egglog, and fails the rule in a head and in a split's case assumptions, where egglog panics. Where 3.0.0 made a panic a no result (`log2`, `BigInt` shifts, `vec-set` and `vec-remove` out of range; `docs/egglog-3.0.0-todo.md`, "Partial primitives return no result"), the library follows 3.0.0. `or`, string `+` and `set-of` take any number of arguments (`VariadicPrimitive`). A comparison is egglog's `bool-<` as a value and its fallible `<` as a filter, and renders so; `set-contains`, `set-not-contains` and `bool-!=` filter as egglog's fallible forms (`!=` for `bool-!=`), and any other filter renders as egglog's `(guard …)`. `ordering-min` and `ordering-max` compare cells, as egglog compares values' representations; in a host read, which never interns, a value no write interned compares above every cell, as egglog's `check` interns it after them, and two such values have no result, since egglog orders them by the order it interns them. A container egglog's `check` interns takes an id there and none here, so the ids after it can differ from egglog's. `birewrite` is `Ruleset.DefineBiRewrite` and `Scope.DefineBiRewrite`, desugared as egglog does (`src/ast/desugar.rs`, `desugar_birewrite`); its `define` adds variables and conditions only, both rules compile before either is registered, and they are published together. Unavoidable in .NET: a `BigInt` result longer than `int.MaxValue` bits throws, failing the rule, on every runtime, where egglog runs out of memory. Primitives take any sort, e-class sorts included, as egglog's do: a class argument is its canonical id where the primitive runs (a rule, a host write or read, a merge), `ordering-min`, `ordering-max` and `bool-!=` compare ids as egglog compares representations, and a user primitive sees classes of the scope that runs it. A class a primitive returns must be usable there: a host write or read checks it and reads it canonically, and a rule's should be one its arguments name, as egglog's primitives return. A host batch refuses a computation over classes after it merges classes, which a later call makes as egglog's next command would; a split's assumptions, an addition computed before the case's unions, compute over values only. egglog's `value-eq`, which its lowering uses for equalities, is `Is` here. And `set-get`, which indexes a set in its elements' cell order, and the zero and NaN a set holds, which an egglog set holds interned: they wait for sets as containers, since a value set is a .NET value, its elements in their own order. Additions, which egglog lacks: a comparison of `f64` values as a `bool` value (rendered `bool-<`), and `set-contains`, `set-not-contains`, `vec-contains` and `vec-not-contains` as one (rendered `bool-set-contains`, `bool-set-not-contains`, `bool-vec-contains` and `bool-vec-not-contains`, names egglog has not); `set-is-empty` and `set-subset`, named so as not to take an egglog name; partial and variadic user primitives. |
| 23 | Serialization | `Scope.Serialize` ports egglog's `EGraph::serialize` (`src/serialize.rs`) and `SerializeConfig` (`SerializeOptions`: `MaxTables`, `MaxRowsPerTable`, `Roots`) over a scope's view, and `SerializedGraph.ToJson` writes the egraph-serialize crate's JSON as its `to_json_file` does. As in egglog: a row is a node `function-{row}-{table}` in its output's class `{type}-{cell}`, the cell canonical; a value is a node `primitive-{class}` of its own class, printed as egglog prints it (Rust's `Debug`), and a set's elements are its children (`set-of`), as a pair's are, under its type's name, and a vector's, under `vec-of`, egglog's `serialized_name`s; an edge into a class takes the class's nodes in turn; a class whose every node was left out is a placeholder `[...]` of infinite cost; a constructor's node costs its declared cost and every other node 1; past the limits, tables are discarded and truncated as egglog's are. A sort's name may hold a dash, as in 3.0.0's class ids (`test_serialize_sort_name_with_dash`), where the pin panics. The JSON is byte for byte serde_json's pretty printing: two-space indents, line feeds, only the quote, the backslash and the control characters escaped, an infinite cost `null`. A row's position is its place in the table's storage, which the engine's tables keep as egglog's do; in a child scope, in the order the engine walks the scope's layers. The departures: (a) A relation's row is a class of its own, of the sort `@{relation}Sort` egglog's desugaring gives a relation (named as its symbol generator names it, skipping a name a user's sort or value type holds, since `@` is not reserved here), numbered by the row, where egglog's is the row's fresh id: here a relation is a unit-valued function (`architecture.md`, section 2.13). (b) A set's elements come in cell order, as egglog's `BTreeSet` gives them, but an element that was never interned on its own has no cell, as serializing never interns: it comes last, in a class `{type}-~{n}` of its own, numbered per type, and a later serialization names it by its cell once another write interns it. (c) A root is a class (`SerializeOptions.Roots`), whose sort is read from the rows that hold it, where egglog takes a sort and a value; a root in no row is refused, where egglog names it whatever it is. (d) There are no `let` bindings in the class data, since a scope has no global `let`; the hidden mirror tables and the built-in contradiction relation, which egglog lacks, are left out. |

## Requirements from the literature review

From the review of the literature on e-graphs with assumptions
([`../history/colored-egraph-literature.md`](../history/colored-egraph-literature.md), including its review
corrections). They bind colored contexts and the lift.

| Requirement | Why |
|---|---|
| The lift must find facts that hold in a case only through an ancestor row mentioning a class's **winner**. With losers-only marking such rows are never copied into the case, so the lift must also look up ancestor rows by each merged class's winner. | With losers-only marking ("Which classes to mark" above), a lift without this misses facts. |
| Each child keeps the member list of every class it merged (the parent-canonical ids in it), and `ScanMerges` is implemented from those lists, reporting a merged class's own canonical id paired with itself when it is a parent id. | Iterating the marked set instead breaks under losers-only marking. |
| A debug invariant checker for contexts, run in tests after every rebuild: overlay keys canonical in the parent once catch-up is done; a child's equalities include its parent's; every hidden row has a reason; child-local ids never appear in an ancestor; cursors valid. | Modelled on Easter Egg's invariants and checks. |
| Inserting a contradiction fact in a case sets the case's stop flag; the rebuild loop checks it; the case answers only `IsContradictory`, is skipped by the lift, and is disposed. | Vacuous cases still copy rows on every merge. |
| Split helpers support demand-driven splitting (split only when it unblocks a rule) and lifting before deepening (lift after each split depth saturates, before nested splits). | Missed ideas from TheSy and Easter Egg; the main defence against case counts growing exponentially. |
| Benchmarks: per-child cost stays flat as the root grows (20k to 2M rows); memory in bytes against full clones on a case-split workload; copy volume per union. | Easter Egg's per-color work never clearly beat clones, the papers count e-nodes only, and a union in a child copies the loser's uses across the ancestor layers. The byte figures are in the [colored-context benchmark reports](../history/colors-m10-reports.md); the timed half is open (`docs/roadmap.md`). |
| The smaller id wins at every level, as in egglog, including when a parent that is not frozen lifts terms after cases created them. | Under a parent that is not frozen, a case-local id can be smaller than the parent's id for the same term, so the parent's id loses in the case and the case hides and copies every parent row that mentions it. Measured in the [colored-context benchmark reports](../history/colors-m10-reports.md): linear in cases times terms per round and independent of the root. Ranking parent-visible ids first would move rewriting of the same order into each case's own layer. Reopen if a user lifts terms in volume. |

## Engine-wide rules that follow

- Visibility (tombstones, and hidden sets in child contexts) is checked on **every** path that yields rows to a
  caller: scans with and without constraints, index builds, refinements, probe results, header subsets, point lookups,
  zero-variable atoms. This fixes egglog's stale-row hole (row 1 of the defect list).
- Every merge path stores the merge function's output and reports only real changes (rows 3, 4, 16 and 17).
- `merge_all` always runs in dependency-stratum order (row 11).
- Every egglog defect in the list ("egglog defects: what the port does instead" in `egglog-engine-map.md`) is fixed
  where it would be ported, with a comment citing the Rust file and line.
